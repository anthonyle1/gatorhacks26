# Incremental evidence and experimental audio

The local SQLite database owns playback occurrences, accepted evidence, recoverable jobs, finish cutoffs, and final results. MongoDB is unnecessary for this pipeline. Review UUIDs stay separate from `yt_<source>` and `ig_<source>` video identities. Existing topic membership IDs (`youtube:<source>` and `instagram:<source>`) remain compatible with saved trees. Playback occurrences identify the review, tab, generation, and frozen segmentation plan; replay/seek/duration changes start new occurrences.

Install `pip install -r requirements.txt` from `backend/`; it includes PyAV, faster-whisper, and the Redis client. Audio is enabled by default. Run one backend process initially: ASR and RoBERTa each serialize local model work; review I/O uses two threads; hosted assessment has an independent semaphore. SQLite leases recover interrupted work after five minutes. Successful processing deletes raw audio. With default `AUDIO_DISABLE_ON_FAILURE=true`, an ASR failure disables audio for that review, discards its remaining queued audio, and retains completed transcripts, metadata, comments and final results. The extension polls the audio status, releases capture tracks, and displays the reason. New review sessions start with audio enabled again; an explicit user opt-out is preserved. Silence/vague or unsupported speech is excluded without disabling working audio. Text and provenance remain in SQLite. Redis has TTLs and falls back to a bounded 2048-entry process cache. Cache misses are coalesced within one process; distributed Redis miss leases are not implemented.

Copy settings from the repository-root `.env.example` into the root `.env`. Enable `REDIS_URL` for reusable text inference and comment snapshots; without Redis the bounded process cache still works. Set `ANALYSIS_CACHE_ENABLED=false` and restart to compare uncached execution. RoBERTa and base.en revisions are pinned to the documented commits. Changing ASR model requires setting its matching `ASR_REVISION`; `main` disables reusable ASR/text inference and scopes other version identities to the process. The text model uses 512-token truncation and batches at most 16 texts, with actual token counts and truncation flags where the tokenizer is available. Comment and transcript sentiment have separate summaries and evidence attribution.

UF NaviGator is the default provider for both video assessments and session topics. Set `NAVIGATOR_TOOLKIT_API_KEY` in the repository-root `.env` using a Toolkit key with access to `gemma-4-31b-it`. The API base is `https://api.ai.it.ufl.edu/v1`, with Bearer authentication and `/chat/completions` requests. Model aliases are provider-specific: use `gemma-4-31b-it`, not the Together alias `google/gemma-4-31B-it`. Configure `NAVIGATOR_TOPIC_MODEL` to use a different permitted model for topics. See the [UF quickstart](https://docs.ai.it.ufl.edu/docs/navigator_toolkit/getting_started/quickstart/) and [UF Gemma model page](https://docs.ai.it.ufl.edu/docs/navigator_models/models/gemma-4-31b-it/).

`NAVIGATOR_RESPONSE_FORMAT=auto` requests JSON schema first. Only explicit unsupported-format errors permit a bounded retry with JSON-object mode and then schema-instructed plain text. Strict local JSON/schema, evidence citation and topic hierarchy validation apply in every mode. Set `json_schema`, `json_object` or `text` explicitly when your model's capabilities are known. A shared deadline bounds format fallback, rate/service retries and one invalid-output regeneration. No browsing/search tools or snippets are sent, even when the legacy Ollama search flag is enabled. Navigator errors retain local analysis and never silently switch providers. `ASSESSMENT_PROVIDER` and `TOPIC_PROVIDER` can each select `navigator`, `gemma` (the alternative Together adapter) or `ollama` (which retains its existing optional Gemini fallback). Model, endpoint and output-mode changes invalidate assessment/topic reuse. The installed environment has no Navigator key, so authenticated live access remains unverified.

To verify your key and model access without sending video evidence, run `python -m analysis.navigator_client` from `backend/`. This uses authenticated `GET /v1/models`. Restart the backend after setting its environment variables. The API key belongs only in backend configuration; never put it in extension files or paste it into chat.

Build `chrome-react` with `npm install` and `npm run build`, then reload the unpacked `dist` extension in Chrome 116+. Open the extension from its toolbar action with a YouTube/Instagram tab selected and press Start tracking. Audio is checked by default, and Start attempts capture automatically. If Chrome requires another supported user invocation, click the Prune toolbar icon again on the actual video tab. Capture failure preserves metadata/comment tracking. Set `AUDIO_ENABLED=false` to disable backend audio, or uncheck Tab audio in the extension before starting. Capture is limited to the selected tab. Stop audio capture or Finish releases tracks; the offscreen document preserves processing when the popup closes. Captured audio is routed back to the speakers so playback continues normally.

If Chrome reports “Extension has not been invoked for the current page,” select the actual YouTube/Instagram tab and click the Prune icon in Chrome's extension toolbar on that page. The toolbar handler records that exact tab/origin, opens the side panel directly from the user gesture, and starts/retries capture when tracking is active. A click inside an already-open side panel does not grant `activeTab`; `chrome://` pages and the extension's full-summary tab are rejected. Switching to another site/tab requires invoking the toolbar on the new video tab. Permission failures display **PERMISSION NEEDED** with these instructions, while metadata/comment tracking remains available.

Both review interfaces show an audio monitor. **NOT RECORDING** means no tab stream is active; an enabled checkbox alone does not mean audio is captured. **CONNECTED — WAITING** means the stream exists but video timing/ownership/playback is not confirmed. **RECORDING** means confirmed video intervals are sampled; the signal indicator distinguishes sound from a silent/muted stream. The monitor separately shows locally saved seconds, pending uploads, accepted backend segments, processing counts, usable transcript excerpts, exclusion reasons and Whisper installation/loading state. It polls the actual backend interpreter, so missing dependencies in a different Uvicorn environment are visible. Final assessments include `evidence_summary.transcript_excerpts` and `transcript_characters`, displayed as the transcript text actually included in that model request. Late transcripts are identified separately from immutable review evidence.

`GET /local-sessions/health` reports ASR package availability and pinned model files without downloading or loading weights. Complete local weights load without a network lookup. ASR results become eligible for Finish before optional RoBERTa startup/inference; the finish deadline also allows expected uploads to arrive before freezing evidence.

The offscreen AudioWorklet collects mono PCM at 44.1 kHz in 2048-sample messages. A dedicated worker uses the locally bundled `@breezystack/lamejs@1.2.7` to encode independent 64 kbps MP3 files; no renamed WebM containers are used. At most two segments wait for encoding. The build includes the LGPL license; encoder source/replacement is available from [upstream](https://github.com/shijinyu/lamejs). The current timing contract accounts for 1104 samples of encoder/decoder delay; real-device offset accuracy remains a rollout measurement. PyAV verifies MP3 codec and bounds decoded samples before inference. ASR resamples to 16 kHz mono, keeps a warm CPU INT8 base.en model, uses VAD and beam size 1, and fully iterates returned ASR segments.

Known finite durations use `ceil(D/15)` equal regions; capture begins at the current watched position and never seeks. Unknown duration uses 15-second rolling regions and flushes partial final audio. The pure `analysis.segmentation` module also provides integer-sample full and sparse plans with an explicit audio budget. The experimental extension currently uses full watched coverage, not sparse sampling. The 15-second target is provisional, not a measured transcription deadline. Pause, rate changes, seeking, navigation, stale timing signals and interruptions split captures. Audio requires a matching active video renderer ID or unambiguous nearby video link; advertisements and unknown DOM ownership are excluded. Site DOM changes may therefore reduce coverage until selectors are updated. Only confirmed intervals enter transcripts; ASR sentences crossing uncertain intervals are excluded. Coverage reports unique media time and repeated capture separately. URL changes alone do not register playback.

Segments use `PUT /local-sessions/{review_uuid}/segments/{segment_uuid}` with `Content-Type: audio/mpeg` and a bounded `X-Segment-Metadata` JSON header. Register ownership first with `POST /local-sessions/{review_uuid}/occurrences`. A segment ID cannot be reused with different bytes or timing. Uploads default to 2 MB and 35 decoded seconds, with 100 pending backend jobs. The offscreen IndexedDB queue allows 32 segments/8 MB, eight attempts and 15 minutes retention. Registration is persisted before upload and retried before Finish. Queue drops/expiry are displayed; expected missing IDs remain explicit in the review manifest. Restarted workers cannot overwrite finalized evidence snapshots.

Finish flushes content and encoder work, waits up to ten seconds for already accepted inference, then atomically freezes the exact manifest and any missing/queued/failed evidence. Late evidence can complete in the live store but cannot change that review or topic tree. A retry uses the same immutable cutoff; to include late evidence, create a new review UUID and new playback occurrences. `GET /local-sessions/{uuid}/evidence` exposes incremental local transcription/sentiment separately from the finalized review; `GET /local-sessions/metrics` reports bounded stage median/p95 samples and cache counters.

The offscreen recorder uses `chrome.runtime` messages to persist status/failure information through the background worker; it never accesses `chrome.storage` directly. Stopping releases tracks and flushes local encoding without waiting for the upload retry queue. Finish gives the recorder ten seconds to acknowledge stopping; if it fails or disappears, the background closes the recorder, retains already queued MP3s/known segment IDs, and marks audio capture uncertain while completing the review with available evidence. If an older extension build shows “Could not flush audio capture,” rebuild/reload the unpacked extension, refresh the video tabs, then retry Finish. Saved pending events and immutable retry snapshots remain in extension storage.

Transcript usability v1 requires English, at least 1.5 seconds recognized speech, recognition log probability >= -1, at least four words and three contextual words outside a small filler list. Silence, missing audio, failed ASR and vague speech remain distinct. This heuristic is provisional and must be calibrated with real clips. `base.en` does not reliably identify unsupported languages; use a multilingual model and matching revision for language evaluation. Excluded text is not sent to sentiment/assessment. Useful title/caption/comments can still support assessment, and useful speech can support assessment without metadata. Topic discovery can use bounded transcript context independently.

Reproduce codec measurements from the repository root:

```powershell
node chrome-react/scripts/benchmark-mp3.cjs
$env:PYTHONPATH = 'backend'
backend/.venv/Scripts/python.exe -m analysis.benchmark --mode decode '.cache/audio-benchmark/*.mp3' --output .cache/audio-benchmark/decoder.json
# Supply representative real speech fixtures to evaluate ASR; first run downloads weights.
backend/.venv/Scripts/python.exe -m analysis.benchmark --mode asr 'fixtures/*.mp3'
backend/.venv/Scripts/python.exe -m pytest -q -p no:cacheprovider
node --test --experimental-test-isolation=none chrome-react/tests/*.test.cjs
```

The initial backend baseline was 90 passing tests in 5.74 seconds; this is regression-test runtime, not model latency. Codec measurements use generated tones, which cannot demonstrate recognition quality. Compare the same short-clip/rapid-swipe/repeat/noisy-speech/silence/weak-metadata/unsupported-language fixtures with current, cached, hosted-without-audio and full-audio configurations. Record cold/warm median/p95, queue wait/depth, uploaded bytes, process memory/CPU, browser Task Manager CPU/memory, playback quality, transcript accuracy and provider cost. Provisional targets are warm transcript p95 <= 10 seconds after segment delivery, bounded queues during 30 minutes continuous playback, no audible playback interruptions, and zero cross-video speech attribution. Browser overhead and accuracy thresholds still require representative real-device measurements. Live Chrome navigation/ad/loop behavior, transcription quality, provider integration and account retention are not certified by mocked tests. Audio defaults on with a session-scoped failure fallback.

Codec smoke measurements on Windows 11, AMD64 Family 25 Model 68, Node 22.14.0 and PyAV 16.1.0 (three warm encoder iterations, four warm decoder iterations):

| Tone duration | MP3 bytes | Encode median / p95 | Decode median / p95 |
| --- | --- | --- | --- |
| 3 s | 24,241 | 385 / 414 ms | 8.5 / 9.0 ms |
| 15 s | 120,372 | 2633 / 2670 ms | 28.0 / 28.8 ms |
| 30 s | 240,326 | 4968 / 5098 ms | 50.7 / 51.0 ms |

These small synthetic samples motivated moving encoding off the timing thread. They do not establish sustained throughput or browser overhead. The first decoder call, including PyAV startup, took 242 ms; subsequent fixture-first calls were warm with respect to the library. Generated reports remain in `.cache/audio-benchmark/`.

A real faster-whisper CPU INT8 smoke run on the 3-second tone completed in 3.59 seconds cold (including model download/initialization), then 23 ms warm. VAD recognized no speech and the transcript was excluded as `no_recognized_speech`; the warm time therefore measures rejection of a nonspeech fixture, not spoken-audio inference. Model files use an explicit local directory under `backend/.cache/asr` to avoid Windows symlink privileges. Speech quality and speech latency remain unmeasured.
